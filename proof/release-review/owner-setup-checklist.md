# figma-drop release setup checklist

This checklist is for the owner of `codlume/figma-drop`. It lists what the unsigned release flow from PR #15 needs now and what a later signed release would need. It contains no credential values. State comes from read-only `gh api` queries on 2026-11-08 (`settings.md`). "Unknown" means that query could not read the value.

Each row has a label:

- **Required now.** The release flow fails without it.
- **Conditional.** It is needed only in the situation named.
- **Optional later.** It is future scope. Nothing here implements it, and this checklist does not authorize it.

## Secrets and variables

The flow needs **no custom repository secret or variable**. Both workflows use only `github.token`, the `GITHUB_TOKEN` that GitHub creates for every run. `.github/workflows/release.yml` and `release-dry-run.yml` reference no `secrets.*` and no `vars.*`. The repository holds 0 secrets, 0 variables, and 0 environments today, and that is correct.

## Optional later: Figma Community publishing

Community publishing is separate from the plugin zip on each GitHub release. The zip needs nothing more. Users unzip it and select **Plugins > Development > Import plugin from manifest** (Figma labels it "Import new plugin from manifest...") in the Figma desktop app. That import is desktop only. Source: [Create a plugin for development](https://help.figma.com/hc/en-us/articles/360042786733).

Publishing to the Community needs these things:

- A Figma account with a public profile as the publisher.
- A plugin ID that Figma assigns, in place of `figma-drop-local`.
- Figma's review.

Sources: [Publish plugins to the Figma Community](https://help.figma.com/hc/en-us/articles/360042293394), [Manifest](https://www.figma.com/plugin-docs/manifest/), [Review guidelines](https://help.figma.com/hc/en-us/articles/360039958914).

**A blocker for figma-drop.** `figma.fileKey` is available only to private plugins and to local development plugins (`enablePrivatePluginApi`). A public Community plugin could not read the file key, so every export would land in Unidentified. That breaks non-negotiable 1. A private organization plugin keeps the key, but it needs a Figma Organization plan or higher. The state of that plan is unknown. Source: [figma global object](https://www.figma.com/plugin-docs/api/figma/).

`networkAccess` to `http://localhost:3579` requires a `reasoning` string, which the manifest already has. Figma prefers `devAllowedDomains` for development-only hosts. Whether review accepts a plugin that depends on a local companion app is undocumented, so it is unknown.

## Optional later: auto-update and other platforms

- **Auto-update.** Electron's `autoUpdater` on macOS uses Squirrel.Mac, and "Your application must be signed for automatic updates on macOS". It also needs a hosted feed. Neither exists. Source: [Electron autoUpdater](https://www.electronjs.org/docs/latest/api/auto-updater).
- **Other platforms.** `scripts/package-local.mjs` and `scripts/release-package.mjs` stop on anything but macOS arm64. Intel macOS, Windows, and Linux are future work.
