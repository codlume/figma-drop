## The question that gates the merge

Merging PR #15 opens or updates a release PR and cannot create a tag or a release.

- `release-please github-release --dry-run --target-branch feat/release-workflow` prints `Would tag 0 releases` (rerun, `dry-github-release.txt`).
- release-please 17.6.0 releases only merged PRs that carry the `autorelease: pending` label (`manifest.js:607-613`). PR #15 has no labels. `gh pr list --state all --label "autorelease: pending"` returns `[]`.
- `release_created` is set only when a release is created (action `index.ts:189-200`). `build` requires it, and `upload` needs `build`.
- `release-pr --dry-run --trace` proposes `0.1.0`. It bumps `package.json`, both app `package.json` files, and `.release-please-manifest.json`, and it creates `CHANGELOG.md` (`dry-release-pr.txt`).

## Checked and sound

- **Pins.** All five action SHAs resolve to their commented tags.
- **Lint.** `actionlint` exits 0. `zizmor --pedantic` reports 0 medium or high findings.
- **Injection.** No `run:` block contains `${{ }}`. A crafted branch name and a crafted release body are not expanded.
- **Forks and the cache.** Fork PRs skip `plan` and run `package` with a read-only token. A cache from a PR or a branch dispatch cannot reach the `main` release build.
- **Tampering.** Every tampered desktop zip fails `codesign --verify --deep --strict`: an extra file, a symlink escaping the bundle, a modified `main.cjs`, and a stripped signature.
- **The plugin zip.** It holds exactly three files, and its manifest is byte-identical to the source.
- **Version sync.** The lockfile stays frozen after a bump to 0.1.0. The GenericJson updater keeps the file's formatting.
- **Leaks.** No proof file leaks a path, username, or token.
